# 特征上界分析：剪枝的「边特征」里到底有没有信息？

> 日期：2026-09-30　｜　脚本：[analyze_feature_ceiling.py](../analyze_feature_ceiling.py)　｜　数据：`report_figs/feat_ceiling_601.npz`
> 结论一句话：**判别信息不在任何单个边特征里，而在「两端径迹起点是否重合」这个对称组合里；而唯一本该携带它的边特征 `log_DOCA` 因为一个公式错误一直是噪声。**

---

## 0. TL;DR

1. **边特征整体无判别力**：原始 5 维 + 派生 9 维 + 次级顶点 3 维，共 17 维，梯度提升树（GBDT）判「真值链内边 vs 跨链假边」的 **AUC = 0.50**（随机）。逐特征看，**33 个特征里最强的单个也只有 |AUC−0.5| = 0.032**。
2. **但一个特定的对称组合很强**：两端径迹「起点位置」（`xProd/yProd/zProd_reco`）的 **3D 距离**，单标量 AUC ≈ 0.62–0.70。
3. **顺带抓出一个真 bug**：`calculate_doca` 的 `t1` 符号写错 → `DOCA`/`log_DOCA` 是错的。证据：① 已知答案算例差 2.0 与 0.8；② **99.5% 的样本违反"DOCA 必然对称"**；③ 与正确值相关系数仅 **0.019**，AUC 0.51 vs 正确值 0.70。
4. **这解释了整条线的一个核心困惑**：我们一直在"往剪枝 MLP 里加更多边特征"（派生 9 维、次级顶点 3 维），而那些通道**本来就没有信息**；而唯一有信息的那条（顶点一致性）从没被正确地构造出来。
5. 训练好的 GNN（v601）在同一任务上 AUC = **0.6268**，**低于**一个只喂两端节点特征的 GBDT（0.70）⇒ 是**模型没用足输入**，不是信息不足。

## 1. 实验设计（原理）

### 1.1 要回答什么问题

在此之前，这一轮所有"模型侧"的改动（加头 / 加损失 / 调采样 / 换排序形式 / 加图结构）**全部无效或为负**；唯一有过正收益的是"给剪枝 MLP 喂物理派生量"（v623/v624）。所以在动结构之前必须先分清：

> 那条缺失的信息，**到底在不在现有输入里**？
> - 不在 → 换输入（要新物理量 / 上游改）
> - 在，但模型用不上 → 动结构 / 动目标

### 1.2 为什么用 GBDT 来回答

**GBDT（Gradient Boosting Decision Tree，梯度提升决策树）**：把许多棵浅决策树顺序相加，每棵新树拟合前面所有树残差的负梯度。本实验用 sklearn 的 `HistGradientBoostingClassifier`（直方图分箱版，LightGBM 同族）。

选它做"上界/天花板"估计，是因为它具备四个恰好需要的性质：

| 性质 | 为什么关键 |
|---|---|
| **非参数、无结构假设** | 不像 GNN 那样受消息传递/嵌入维度的限制；能逼近任意（给定特征下的）非线性边界 |
| **能吃任意特征组合** | 树天然做特征交互 ⇒ 只要某个组合有信息，它就能挖出来 |
| **逐样本独立（不看上下文）** | 因此它是"**仅凭这些特征**"的可达上界；GNN 若低于它，说明模型没用好输入（而不是信息不够） |
| **可解释（permutation importance）** | 直接指出信息在哪几个特征上 |

**注意它的边界**：GBDT 逐边独立、**不使用事件上下文**。所以它是"无上下文上界"，既不是端到端性能的预测，也不能否定"上下文能带来更多信息"。

### 1.3 数据与切分

- 数据：0904 测试集，前 2 个 chunk，**246 个事件**；
- 样本：tt 边中属于"难池"的那些 = **真值链内边（y>0）** ∪ **跨链假边（两端都是真值径迹但不同链）**；
  共 **4604 条**（真 2218 / 假 2386）；
- **切分按事件**（70% 事件训练 / 30% 测试）：同事件内的边高度相关，按边随机切会严重高估泛化；
- 三类结果用 3 个随机种子重复，确认稳健。

### 1.4 特征分组（共 33 维）

| 组 | 维度 | 内容 |
|---|---|---|
| ① 原始 tt 边特征 | 5 | `FromSameAssociatedPV_reco`, `theta_reco`, `trdist_reco`, `delta_z0_reco`, `log_DOCA_reco` |
| ② + 派生（三角传递） | +9 | ΔR, m, \|Σq\|, ΔpT, ΔIP, rk, Δz, sup, rk_aff（即 v624 用的那组） |
| ③ + 次级顶点一致性 | +3 | zcpa, flight, collinearity（即 v636 的 `derived_vertex`） |
| ④ + 两端节点特征 | +16 | 每条径迹的 `px,py,pz,xProd,yProd,zProd,Charge,Prob_ghost` × 2 端 |

## 2. 结果

### 2.1 分组 AUC（按事件切分，3 个种子）

| 特征组 | 维度 | AUC (seed 0/1/2) | AP |
|---|---|---|---|
| **①→③ 全部边特征** | 17 | **0.502 / 0.492 / 0.494** | 0.43 / 0.50 / 0.50 |
| 仅两端"起点" 3D 坐标 | 6 | 0.659 / 0.627 / 0.630 | 0.58 / 0.59 / 0.61 |
| 两端节点特征 | 16 | **0.708 / 0.684 / 0.645** | 0.63 / 0.68 / 0.62 |
| 全部 | 33 | 0.704 / 0.687 / 0.646 | 0.62 / 0.68 / 0.62 |

### 2.2 逐特征 AUC：**没有任何单个特征有用**

33 个特征里，最强的单个是 `sup`（三角支撑度），AUC = **0.5324**（\|AUC−0.5\| = 0.032）；最弱的一批（`delta_z0`、`dz`、`Charge`）恰好 = 0.500。

⇒ **不存在"某个量稍加利用就能提升"的捷径**。

### 2.3 但有一个特定组合很强

把两端径迹的起点位置相减取模：

| 量（物理单位） | 真边中位 | 假边中位 | AUC |
|---|---|---|---|
| **\|Δ起点\|（3D）** | 小 | 大 | **0.6203** |
| **正确重算的 DOCA** | 小 | 大 | **0.7006** |
| 仓库现用的 `log_DOCA` | — | — | 0.5095 |
| 仓库现用的 `trdist` | — | — | 0.5295 |

（在归一化单位下 \|Δ起点\| 的 AUC 为 0.296，即取向 0.704 —— 归一化会改变各分量权重，所以上表用物理单位为准。）

**这就是全部线索**：信息存在于"两条径迹是否源自同一个点"这个**特定对称组合**里，而不在任何单个输入量里。

### 2.5 两个补充实验：修好 DOCA 能多赚多少？上下文有没有额外信息？

**(A) 把"正确 DOCA"加到节点特征之上**

| 特征 | AUC（3 seed） | AP |
|---|---|---|
| 节点 16（baseline） | 0.679 (0.708 / 0.684 / 0.645) | 0.643 |
| 节点 16 **+ 正确 DOCA** | **0.738** (0.763 / 0.713 / 0.738) | 0.703 |
| 节点 16 + 正确 DOCA + \|Δ起点\| | 0.745 (0.760 / 0.728 / 0.747) | 0.708 |

⇒ 正确 DOCA 在节点特征**之上**还有 **+0.059 AUC** 的独立信息 —— 它不是"起点距离"的重复，而是**线线几何**带来的额外判别力。这同时给出了"DOCA bug 让性能被低估多少"的**特征层面度量（≈ +0.06 AUC）**。

**(B) 上下文假设（信息是"绝对"的还是"事件内相对"的？）**

| 特征 | AUC |
|---|---|
| 节点 16 + 绝对量（正确 DOCA + \|Δ起点\|） | **0.745** |
| 节点 16 + **事件内相对排名**（pct rank within event） | 0.701（**更低**） |
| 绝对量 + 事件内相对排名 | 0.742（略降） |

⇒ **加入"事件内相对量"没有收益**。也就是说：这条顶点一致性信息是**逐对（pairwise）的绝对量**，不需要"与事件内其他候选比较"。

**这条结论很重要**：它说明**"上聚类/注意力/顶点 token 这类需要上下文的机制，其收益假设并不成立"**（至少对这个任务）。也顺带解释了为什么"GBDT ≥ GNN"不是悖论 —— 如果信号本身是逐对的，那 GNN 的邻居聚合本来就没有额外信息可取，而它还要背 6 个任务的共享编码器。

### 2.6 GBDT 结论的**边界**（不要过度解读）

GBDT 是"给定特征下的可达下界"（树是通用逼近器），所以 **"节点特征含 ≥0.70 信息"是硬结论**。但它**不能**证明"边特征的信息严格为零"，只能排除**可检测**的效应：

- 样本 3084 训练 / 1520 测试边，AUC 的标准误约 0.015 ⇒ **AUC ≲ 0.53 的弱信号不在检验能力之内**；
- 逐边分类器**看不到上下文**（但 (B) 已部分排除了这一条）。

因此严谨表述应为：**"现有边特征里可检测的判别信息 < ~0.05 AUC"**，而不是"绝对没有信息"。

---

### 2.7 与 GNN 的对比（以及为什么"GBDT 更好"不是悖论）

| 模型 | 同一任务的 AUC |
|---|---|
| GNN（v601，bench v2 的 `auc_fake_inter`） | **0.6268** |
| GBDT，只喂两端节点 16 维 | **0.70**（+ 正确 DOCA 可达 **0.74**） |

表面上"逐边独立的树模型打败了带上下文的 GNN"像是悖论。但结合 2.5(B) 就说得通：

- 这个任务的信号是**逐对的绝对几何**（起点是否重合 / 线线距离），(B) 显示**上下文的相对信息并不存在**；
- 于是 GNN 的邻居聚合**本来就没有额外信息可取**，而它同时还得背 6 个任务的**共享编码器**（多任务干扰）与为**全局池**（99.7% 易负例）优化的损失；
- 所以 **"GNN ≤ GBDT" 应当读作"当前模型的容量/目标没有对准这个局部子问题"，而不是"GNN 这个架构不行"**。

⚠️ 注意这个比较**不是严格同口径**：GBDT 在 246 事件里按事件留出的测试集上评；GNN 的 0.6268 来自 `analyze_prune_loss.py` 的 200 事件、且正例池是"全部真边"。要把它变成硬结论，应在**同一批边、同一任务定义**上重跑两者。

## 3. 顺带发现的 bug：`calculate_doca`

### 3.1 DOCA 是什么、干什么用

**DOCA = Distance Of Closest Approach（最近接近距离）**：两条**直线**之间的最短距离。

在顶点重建里的地位：来自**同一个衰变顶点**的两条径迹共点 ⇒ DOCA ≈ 分辨误差；来自**不同顶点**的径迹一般不相交 ⇒ DOCA 显著大于 0。它是传统顶点寻找/拟合（Kalman 顶点拟合、自适应顶点拟合 AVF、含入式顶点寻找 IVF）最核心的判别量之一，也是 b-tagging 的基础量。

在我们的图里，`log_DOCA_reco` 是 **tt 边 5 个特征里唯一的"配对几何"量**（`FromSameAssociatedPV_reco` 是 PV 归属的布尔量、`theta_reco` 是夹角、`trdist_reco` 是横向投影、`delta_z0_reco` 是 z 差），所以它理论上应该是边剪枝**最强的判据**。

### 3.2 错在哪

[quantity_calculation.py](../..) `calculate_doca`（定义在 `DFEI_IFT_20260904/dfei_repo/preprocessing/calculator/quantity_calculation.py`）：

```python
delta_r0 = p1_r0 - p2_r0                      # w
dr_dot_u1 = (delta_r0 * u1).sum(axis=1)       # d = w·u1
dr_dot_u2 = (delta_r0 * u2).sum(axis=1)       # e = w·u2
u1_dot_u2 = (u1 * u2).sum(axis=1)             # c = u1·u2
denom = 1.0 - u1_dot_u2 ** 2
t1 = -(dr_dot_u1 + u1_dot_u2 * dr_dot_u2) / denom   # ← 错: 应为 (c·e − d)/denom
t2 =  (dr_dot_u2 - u1_dot_u2 * dr_dot_u1) / denom   # ✓ 对
delta = delta_r0 + u1*t1 - u2*t2
```

最小化 `|w + t1·u1 − t2·u2|²` 的正确解（令 `c=u1·u2, d=w·u1, e=w·u2`）：

```
t1 = (c·e − d) / (1 − c²)        ← 仓库写成了 −(d + c·e)/(1−c²)
t2 = (e − c·d) / (1 − c²)        ✓
```

另外两处**次要问题**：
- `mask_parallel = u1_dot_u2 == 1.0` 用**浮点精确相等**判平行（真实平行是零测集）⇒ 近共线对落入 general 分支，`denom → 0` 使 DOCA 爆炸（没有 `|denom|` 保护）；
- "平行"分支用 `|w|`（起点间距）而 general 分支用线线距离 ⇒ 两支定义不一致。

### 3.3 三条独立证据

**证据 1：已知答案的算例**（两直线相交，正确 DOCA = 0）

| 算例 | 仓库 `calculate_doca` | 正确 |
|---|---|---|
| 两线过同一原点 | **2.000** | 0.000 |
| 两线共点（另一组） | 0.000 | 0.000 |
| 两线共点（第三组） | **0.800** | 0.000 |

**证据 2：对称性（数学上必然成立的判据）**
线线距离与"哪条叫 1"无关 ⇒ 正确实现必须满足 `DOCA(1,2) == DOCA(2,1)`。
把 3000 组随机 (位置, 动量) 的 1↔2 完全交换后重算：

```
不对称比例 = 99.5%      最大相对不对称 = 0.971
```

**证据 3：判别力与相关性**

| 量 | AUC |
|---|---|
| 正确重算的 DOCA | **0.7006** |
| 仓库 `log_DOCA` | 0.5095 |

`corr(仓库 log_DOCA, 正确 log_DOCA) = **0.0189**` ⇒ 现用特征与正确值**几乎完全不相关**，等于往网络里喂了一个**噪声列**。

### 3.4 影响有多大

- `log_DOCA_reco` 是边头唯一有物理内涵的配对几何量，**它坏了 ⇒ 边头只能靠 GNN 把节点信息"揉"成边表征**（而它只做到 0.63，低于逐边 GBDT 的 0.70）。
- 这**很可能就是"边剪枝一直做不好"的直接原因之一**：最好的那条通道被一个符号错误堵死了。
- 受影响范围：**所有用 `DOCA` / `log_DOCA` 的模型与数据**（0702 与 0904 都是）。`delta_z0` 不受影响（它是 `delta_r0[:,2]`，不经过 `t1`），所以此前 0702 的 dz 泄漏分析仍然成立。

### 3.5 其余算子的审计（有没有同类错误）

| 算子 | 产出 | 审计结论 |
|---|---|---|
| `calculate_doca` | `DOCA`, `log_DOCA`, `delta_z0` | ❌ **t1 符号错**（+ 近共线无保护 + 平行支不一致）|
| `calculate_transversedist` | `trdist` | ⚠️ 用了**随机轴** `x_prime = randn(...)`，但最终标量 `sqrt((x1−x2)²+(y1−y2)²)` 是绕 z′ 旋转不变的 ⇒ **数值上是确定且可复现的**（此前的说法要更正）。它等于"Δ起点在垂直于 (p1+p2) 平面上的分量"，物理上合理但比 DOCA 弱 |
| `calculate_samepv` | `FromSameAssociatedPV` | ✓ 对称、正确（但在难池内近乎常数，属数据性质不是 bug）|
| `calculate_angle` | `theta` | ✓ 对称、正确 |
| `calculate_ip` | `log_minIP` | ✓ 正确（PV 到径迹线的垂距）|
| `apply_log_transform` | `log_*` | ✓ `log(x+1e-5)` 对正值量安全 |

⇒ **确认 1 个真 bug（DOCA），1 个坏实践（随机轴，数值无害），其余正常。**

## 4. 结论与下一步

### 4.1 "边信息不重要" vs "边剪枝重要" —— 两者不矛盾

- 之前说**边剪枝重要**，指的是它的**任务位置**：边决定链是否连通，是瓶颈的一半。这一点没变。
- 现在说**边特征无用**，指的是那 5 个**手工输入特征**不含信息。
- 而且要澄清一个常见误解：**边剪枝头并不只吃那 5 个边特征**。它吃的是 `block.edge_logits[tt]` —— GNN 消息传递后的**边表征**，里面主要装的是**两端节点表征 + 邻居上下文**。所以"边剪枝"实际的信息来源一直是**节点**。
- 于是三者合起来正好解释现状：
  1. 喂进剪枝 MLP 的手工边特征是噪声（含一个算错的 DOCA）；
  2. 唯一有效的替代路径（靠消息传递把节点信息学成边表征）没被 GNN 用好（0.63 < 0.70）；
  3. 而我们一直在第 1 条通道上做加法（派生 9 维、顶点 3 维）——**在一条没有信息的通道上加东西**。

### 4.2 该怎么做：把节点信息以**对称**方式放进边

边的方向在 0904 里是任意的（已修掉顺序泄漏），因此任何由两端构造的边量都**必须对交换 (i,j) 不变**。建议的对称边特征（全部可由现有节点量算出，**不需要新数据**）：

| 建议边特征 | 对称性 | 依据 |
|---|---|---|
| **\|Δ起点\|**（3 分量绝对值 + 模长） | ✓ | 实测 AUC 0.62–0.70 |
| **正确的 DOCA + log** | ✓（线线距离天然对称） | 实测 AUC 0.70；**必须先修上游或用本地正确实现** |
| \|Δz\|、ΔR(ηφ)、θ（夹角）、不变质量 m | ✓ | 经典配对量 |
| \|ΔpT\|、\|ΔIP\| | ✓（**必须取绝对值**） | 不取绝对值会退化成方向信息 |
| ⚠️ `delta_z0_reco` | ✗ **反对称** | 现用值虽已无泄漏，但符号仍是无意义的"方向"；若要保留应改为 \|Δz\| |

并配一条**边级辅助监督** `same_vertex(i, j)`（真值由 MC 母粒子/生产顶点给出）—— 直接对缺失的那条信息做监督，而不是让模型从剪枝目标里间接猜。

### 4.3 两个上游动作（建议同步给 yukai）

1. **修 `calculate_doca`**：`t1 = (u1_dot_u2*dr_dot_u2 - dr_dot_u1)/denom`；平行判据改为 `|1 - u1_dot_u2| < eps`（并对 `denom` 加保护）。修好后**重做数据**，因为所有历史模型都吃了这个错特征。
2. `trdist` 的随机轴建议换成确定性构造（数值虽等价，但可读性与可复现性差）。
